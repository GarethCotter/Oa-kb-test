Not possible, not supported, cannot be done, is there a way to, does the system allow,
QR code per delegate, reset submission numbering, edit an invoice, attendees editing
their own registration, redirect the homepage, host a template file.

Confirmed limitations. Answer these plainly — a clear "no" is more useful than a
workaround that doesn't exist.

- **Changing fonts** — you cannot change fonts on Oxford Abstracts software.
- **Visa / invitation letters** — there is no feature to generate visa support letters.
  Submitters asking about this should contact their event administrator.
- **DOIs** — Digital Object Identifiers are not supported.
- **Duplicating or cloning a question** — not possible.
- **Importing sessions in bulk / via CSV** — not possible at this time.
- **Italics on the review form** — not available.
- **Changing the "Get tickets" button wording** — the button text cannot be changed.
- **Hyperlinks in a ticket description** — not currently possible, but planned.
- **Checking for duplicate IDs in the programme** — not supported. Workaround:
  Conference > Program > Sessions > Submission IDs.
- **Group tickets** — you cannot buy a "group" ticket, but an attendee can buy multiple
  tickets and name the other ticket holders on the registration form.
- **A mobile app** — there is no Oxford Abstracts app.
- **Re-running auto-assign for some submissions only** — re-running auto-assign
  re-assigns all submissions.
- **Committee members building the programme** — only admin users can create sessions
  and allocate presentations to them.
- **Multiple users editing the same abstract** — only the person who submitted it can edit it.
- **Admins changing a reviewer's email** — reviewers must change it themselves from their
  own account.
- **Admins changing an attendee's name** — attendees do this from their profile page.
- **Admins changing a submitter's email address** — only the submitter can, from
  My Profile.
- **Authors and affiliations on the decisions table** — that data appears only on the
  Submissions table accordion rows, not the Decisions page.

Added from a year of support replies, July 2026:

- **A QR code or barcode per registrant** — not possible. The system produces one
  common code for the whole programme, not an individual code on each delegate's name
  badge. This is the single most-asked limitation, and there is no workaround inside
  Oxford Abstracts.
- **Resetting submission numbering** — not possible. Deleting a submission does not
  truly delete it, so its number is never released and the sequence keeps counting.
- **Attendees editing their own registration answers** — attendees cannot go back and
  change what they entered; the organiser has to amend it for them. Not on the roadmap
  as of mid-2026, though it has been raised with the product team. (They *can* change
  their own name and email from their profile page — that is different.)
- **Editing an invoice or receipt yourself** — organisers cannot change the name,
  organisation or line items on an issued invoice or receipt. Oxford Abstracts support
  has to make the edit; ask them, then download the corrected file from the
  registrations table.
- **Redirecting the conference homepage to a website-builder site** — not possible.
  Hide the conference homepage instead; see the website builder note.
- **Hosting a downloadable file, such as a Word template, on the submission form** —
  the form can only link out to an external URL, so the file has to live somewhere
  else (your own site, a shared drive) and be linked from there.

From a further pass over the same year's replies, July 2026:

- **An audit log or change history** — no record of which admin changed what, and no
  tracker of what a submitter altered.
- **Renaming or reordering stages once created** — the only route is new stages, move
  the submissions, delete the old ones, which is unwise once submissions exist.
- **Hiding an individual session** from the public programme — publish or unpublish
  the whole programme only.
- **Duplicating a question** on the submission form, and only one authors question and
  one category question per form.
- **A second review form** — one per stage. Different criteria per category need
  separate stages.
- **Rejection sub-types** — only acceptance supports types. The decision list itself
  (Pending, Accepted, Rejected, Withdrawn) is fixed and cannot be switched off.
- **Sponsor levels beyond Gold, Silver and Bronze** — hard coded and shared by every
  event, so they cannot be renamed or added to. Only one sponsor shows in the
  programme side menu.
- **Bulk importing registrations**, and **no check-in function** at the event.
- **Guest ticket checkout** — anyone buying a ticket must register or log in.
- **Embedding the submission form** in an iframe; only the programme can be embedded.
- **URL redirects** for programme pages.
- **Bulk changing abstract titles** between sentence and title case — one at a time in
  the submissions table.
- **Capping submissions per submission type** — monitor and hide the option when full.
- **Telephone support** — email, or book a support session.
