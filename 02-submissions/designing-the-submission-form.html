Designing the submission form

Learn how to design the submission form so you can collect the information and data you need.#

Note

Not all of the features below are available in the free package. To see what is included, see The essential abstract management tools.

To view, design or edit your form, go to Event dashboard → Abstract management → Submissions → Form & setup.

Your questions are listed down the page in the order submitters will see them, with a row of buttons above them.

Form status#

The button at the top left shows whether your form is open or closed. Click it to open the Form status panel, which has three separate switches:

  • Open for new submissions
  • Allow edits to complete submissions
  • Allow edits to incomplete submissions

These are independent, so you can close the form to new submissions while still letting people finish or correct what they have already sent. When all three are off, the status reads Form closed.

Note

Setting a deadline on your event does not close the form. You have to turn these switches off yourself. See Opening and closing submissions (deadlines).

Preview and test form#

Preview and test form opens your form in a new tab exactly as a submitter sees it, and lets you complete it as a test.

Note

If your form is closed, you will see a message saying submissions are closed for submitters but that you can still create them as an admin. That is expected — it means you are seeing the form through admin permissions, not what a submitter would get. To check what submitters actually experience, use Copy submission link and open it in a private window with an account that has no admin rights.

Copy submission link#

Copy submission link copies the address to give to submitters. Put this on your website and in your call for abstracts.

Header and footer#

Header and footer opens two rich text editors — Form header and Form footer — for the messages that appear at the start and end of the form. Both allow fonts, sizes, alignment, colours, tables, images and links.

Edit what you need and click Back to form. Changes save automatically.

Combined word limits#

Combined word limits applies a single shared word count across several questions at once — useful when the total length matters more than any one field. See Combined word count.

Submission fees#

Submission fees is where you connect a payment provider so submitters pay when they submit. You can connect PayPal or Stripe. Until one is connected, the panel tells you to pick a provider. See Charging a fee for submission.

Adding a question#

Click + Question at the top of the form. The question types are grouped — standard, read-only, text, checkbox, dropdown, multimedia and other.

Click the type you want. Its editor opens straight away with the fields for that type, and you click Create question at the bottom when you are done. Back to question types returns you to the list without creating anything.

Note

The Standard questions group only offers the standard questions you do not already have. Each one can appear once per form, so a form that already uses most of them will show a short list — or just one. Nothing is wrong; the missing ones are already on your form further down the page. See Submission question types.

Editing a question#

Click any question in the list to open its editor. Changes save automatically.

What you see depends on the type. A text editor question — the abstract is one — has:

  • Question name (required)
  • Word limit and Character limit, both optional
  • Answer is submission title — tick this if the answer to this question is the submission's title. Only one question per event can be the title, and this is what emails to submitters use to name the submission.
  • Text editor type — how much formatting the submitter gets
  • Description — the wording of the question as the submitter reads it

Preview question shows that single question as a submitter will see it, and Delete question is in the same bar.

Note

The Description editor gives you underline, strikethrough, links, fonts and colours. Submitters do not get those. What a submitter can use is set entirely by the Text editor type you choose, so check that rather than the toolbar in front of you.

Question type and settings#

At the bottom of every question editor, and on each question's row in the list, are two groups of settings.

Question type decides whether an answer is needed:

  • Optional — the submitter can leave it blank
  • Required — an answer is needed, and a submission without one is marked incomplete
  • Read-only — the question is visible but cannot be answered, typically where an answer already exists and you do not want it changed
  • Hide — the question is not shown to the submitter at all
Note

A question that is Required but also hidden or read-only will mark submissions incomplete, because nobody can answer it. A red marker appears next to any question in that state.

Settings decides where an answer goes. Each is independent, and questions that take no response do not have all of them:

  • Show to reviewer
  • In abstract book
  • In program
  • In poster gallery
  • Dependency question — see Dependency questions
Tip

If reviewers report seeing only the title, or an abstract book comes out containing nothing but titles, these checkboxes are the first thing to look at. They are set per question.

Questions that only display text, such as a Text block or Page break, offer just Show and Hide, because there is no answer to require.

Deleting a question#

Open the question and click Delete question, then Back to form. You can restore a deleted question later, along with any responses already given.

Note

Deleting questions in multi-stage events may have unintended consequences. See Setting up a multi-stage event.

Changing the order of questions#

Drag a question up or down by the handle on the left of its row. The order on this page is the order submitters see.

What a submitter sees when something is missing#

It is worth completing a test submission before you open your call, because the form does not simply refuse an incomplete answer.

If a submitter presses Submit with required questions unanswered, they get a Submission incomplete message listing each question that still needs an answer, and a choice between going back and submitting anyway. If they submit anyway, the submission is saved and marked incomplete, and they can come back to finish it while edits are open.

Note

The authors question has its own rule. Exactly one author must be marked as presenting, and a submitter who has marked none — or more than one — is told so by name at this point. You set how many presenters are allowed in The authors and affiliations question.

Incomplete submissions appear in your submissions table so you can see who has started but not finished. See The submissions table, including incomplete submissions.
